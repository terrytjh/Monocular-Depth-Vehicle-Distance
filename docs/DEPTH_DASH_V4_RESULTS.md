## 4. 台灣網路行車影片 18 支(只評自車速,弱真值)

- 封存後打開保險箱的原檔:18 支中**只有 2 支畫面上有車速**。一支是行車記錄器內建疊字(車速旁有 GPS 座標),一支是 GPS 記錄器疊字;
  其餘 16 支的疊字是上傳者的標誌、路名橫幅或時鐘。逐秒讀了車速(每個 1 秒區間中點的影格,共 360 秒,沒有讀不出的),
  頭尾時鐘相隔與影片長度相符。原檔與遮罩版的影格以畫面上半部比對,位移為 0 格。
- 對疊字車速的差距(方法 − 疊字;登錄寫「逐秒」,不調延遲):

| | 深度法(第四版 = 第三版的尺) | 標線幾何法 |
|---|---|---|
| 行車記錄器疊字那支(120 秒,18–91 km/h) | 3.12 km/h(偏差 +1.25,95% 一致界限 −6.3 ~ +8.8),107 秒有值 | 4.52(−3.82),120 秒 |
| GPS 記錄器疊字那支(240 秒,89–130 km/h) | 9.28 km/h(+1.87,−24.1 ~ +27.9),200 秒 | 5.77(+1.62),232 秒 |
| 兩支合計 | 7.14 km/h(+1.65),307 秒 | 5.34(−0.23),352 秒 |

  GPS 記錄器那支的疊字每 10 秒會往下跳約 3 km/h(讀值如實記錄),參考值本身不平順。
- 有輸出的片:深度法 9/18、第四版 7/18(需要標線幾何法)、標線幾何法 7/18。拒發的片多半「完全找不到虛線週期」。
  **封存後的檢查(不是登錄的分析)**:拒發的片畫面地平線低、沒有引擎蓋,路面與虛線幾乎都在畫面高度 74% 以下,
  而第一版起的自動規則把分析範圍下緣固定在最多 0.74(為底部有疊字帶的片設計),最清楚的近處虛線被切掉。
  這是方法的設定問題,不是影片品質;改法在下一版的登錄中說明。
