# 台灣行車紀錄器第一次盲測事前登錄:第十二版自車速(2026-11-15)

登錄時還沒有任何程式讀過盲測片(只有 2026-10-25 列出的檔名與檔案大小)。本文件與程式 commit 並推上 GitHub 之後,才從外接硬碟複製盲測片。

## 0. 登錄前已知的事

- 相機:自己的後視鏡型行車紀錄器,前鏡頭 1920 × 1080、25 fps,畫面左下有疊字的 GPS 車速。疊字車速是參考值,不是真值;方法減疊字叫「差距」。台灣只評自車速。
- 資料切分(2026-10-25、10-28 定,當時只看過檔名):開發 = 9/21、9/23、9/24 的 226 支(疊字車速讀過);**第一次盲測 = 9/26–10/3**(本登錄);10/4 以後的檔保留、不碰。
- 開發(答案看過,不是證據)時發現並處理的事:
  - 相機繞鏡頭軸歪約 4–5°(兩份獨立計算一致),左右兩條車道線的相機常數 A 差約 23%;第十一版的補位兩條線用同一個 A,左線偏快、右線偏慢 → S1。
  - 拒發段的補位偏差和該段估的地平線有關(33 段相關 0.93);這台相機各趟的地平線 384.5–387.1 px → S3。
  - 停車時第十一版的補位仍給讀值(平均絕對差 13.5 km/h)→ S2。
  - 疊字車速在高架橋下等地方會停在舊值或自己飄(看圖確認 3 例),這些秒不排除。
  - 「疊字車速 × 虛線經過同一列的時間」量到的虛線週期是 9.85 m(同一量法在 comma2k19 量到 14.59 m,法定 14.63 m);第十版讀值比疊字高約 2% 有一部分來自這裡,分不出是路上的線還是疊字車速。
  - 時速 30 以上的覆蓋率(開發 66%)受限於追不到車道線,這一版沒有改。

## 1. 方法

### 1.1 第十二版 = 第十一版 + 三個改動

- 第十一版:`docs/DEPTH_DASH_V11_PREREG.md` 的流程與參數,用開發批次的同一套流程(`tools/v12/dod_pipeline/` 是開發時用的四支流程程式的逐位元組複本;參數檔只把 K4 的畫面寬改成 1280)。
- 改動在 `tools/v12/v12_post.py`,加在第十一版的 post 步驟上,其餘步驟與參數不變。三個改動都關掉時輸出與第十一版逐字相同(開發 225 支、comma2k19 第 9 包 210 段都核對過)。
  - **S1** 補位(主要組 MH)每條車道線用自己那一側的相機 A(`tools/v12/car_a_sides.py`)。
  - **S3** 拒發段:該段的地平線和相機平常的地平線(其他趟各趟中位的中位)差超過 0.007 × 畫面高(720p 約 5 px),不給補位。
  - **S2** 停車:每秒相鄰兩幀的光流(`tools/v12/stationary.py`,縮到 320 px 寬,路面帶內的第 90 百分位)< 0.2,且連續 ≥ 3 秒,這些秒的自車速 = 0 km/h(95% 半寬 3 km/h)。
- 第十版、第十一版、第十二版同一次跑、一起封存,在同一批上比較。

### 1.2 固定的常數(全部只從開發 226 支來,盲測片上不學任何東西)

`tools/v12/dod_blind_constants.py`:開發時每一段用「其他趟」的常數;盲測片的每一趟都不在開發批次裡,所以用開發批次全部的趟。

| 常數 | 值 |
|---|---|
| 深度法的相機 k(白天) | 0.7828(開發 54 段、6 趟的中位) |
| 夜間相機 k | 沒有(開發批次沒有可用的夜間段,和開發時相同) |
| 相機 A(第十、十一版) | 1,170.1 |
| 每側相機 A(S1) | 左 996.0、右 1,286.4 |
| 相機地平線(S3,720p) | 386.6 px |
| 路面帶下緣 | 0.769(開發批次的值) |

- 組別:灰階 < 50 = 夜間,其餘 = 主要組(和開發相同);主要組是主要成績。
- 影格:從原尺寸第 864 列起塗黑、縮到 1280 × 720;程式逐張檢查「y ≥ 870(720p 為 580)每個像素都是 0」。
- 影格檢查不過的片(幀率不在 24.95–25.05、解不出來等)在任何預測之前排除,結果文件列出支數。

### 1.3 開發資料上的結果(答案看過,不是證據)

## 2. 資料:9/26–10/3 抽 60 支

- 母體:2026-10-25 列的前鏡頭檔名清單裡,檔名日期 2026-09-26 到 10-03 的 463 支。
- 趟:照檔名的開始時間排序,和前一支的開始時間相差超過 150 秒就是新的一趟(60 秒一支,等於前一支結束後超過 90 秒);共 23 趟。
- 抽法(`tools/v12/dod_blind_prepare.py draw`,只讀檔名清單):`random.Random(20261113).sample(母體, 463)` 當順序,依序取,同一趟已取滿 4 支就跳過,取滿 60 支為止。抽到 22 趟。
- 2026-11-14 曾用同一個種子不分趟抽過一份名單(沒有打開任何片),改成每趟最多 4 支後沒有使用。
- 複製:`dod_blind_prepare.py copy` 先確認本文件已在 origin/main,才從外接硬碟複製 60 支到 D 槽,並逐支核對 sha256。

## 3. 參考值與評分

- **封存之後**才用 `tools/dod_osd.py --set blind1 read` 讀盲測片的疊字車速(只讀車速與時鐘,不讀位置)。它先執行 `tools/v12/dod_seal_check.py check`:五份封存摘要已 commit 且在 origin/main、私下的完整封存檔與摘要相符、每個預測檔的 sha256 沒變、每支片都在封存裡;任何一項不符就拒絕。
- 封存:`tools/seal_predictions.py` 對第十、十一、十二版的逐片檔與第十一、十二版的逐秒自車速各做一份。完整封存檔的檔名帶有行車的日期時間,只放 D 槽;commit 的是每份封存檔的 sha256 摘要(`docs/seals/dod_blind1_*_seal.json`)。
- 比對:`tools/dod_compare.py`(開發用的同一支),不平移時間;數字由 `tools/v12/dod_blind_score.py` 算(在開發資料上重現 1.3 節的表)。
- 疊字卡住的秒不排除,所有成績照算。結果文件另外寫出「方法判停車、疊字 ≥ 5」的秒數,只當描述。
- 不確定度:以片為單位的 bootstrap 2,000 次(seed 20261016)。

## 4. 流程

1. 本文件與程式 commit,推上 GitHub。之前不碰盲測片。
2. `dod_blind_prepare.py copy`、`tags`(只讀容器的時間表,不解碼)。
3. `tools/v12/dod_blind_run.sh`:塗黑影格 → 名單與組別 → 常數 → 工作複本(和開發批次的流程程式逐檔相同才繼續)→ 第十、十一版 → 第十二版 → 封存與摘要。封存前沒有人看盲測片的畫面(盲測模式不產生縮圖)。
4. 五份摘要 commit、推上 GitHub。
5. `tools/v12/dod_blind_after_seal.sh`:核對封存 → 讀疊字 → 比對 → 9 條預期;結果寫 `docs/DOD_V12_BLIND_RESULTS.md`。
6. 這 60 支只用一次;結果出來後不再用它們調任何參數。
